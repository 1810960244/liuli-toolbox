## 图 1 · 部署架构

```mermaid
flowchart TB
    subgraph C["客户端"]
        direction LR
        BR["浏览器 / PWA<br/>38 个工具"]
        APK["Android App<br/>WebView 壳 + 下载桥"]
        BLOG["博客<br/>www.liulichat.cn"]
    end

    subgraph E["nginx · 443 · Let's Encrypt"]
        NG["三站点反代<br/>HSTS / CSP / gzip"]
    end

    subgraph S["阿里云 Debian 13 · www-data 运行"]
        direction TB
        TB["toolbox.service<br/>python3 · 127.0.0.1:8792<br/>既是 API 又是站点"]
        AC["liuli-account.service<br/>node · 127.0.0.1:8791"]
        DB1[("toolbox.db<br/>SQLite<br/>云同步 / 埋点 / 博客")]
        DB2[("accounts.db<br/>SQLite<br/>账号 · bcrypt 哈希")]
        BLOGST["/opt/blog<br/>纯静态产出"]
    end

    subgraph X["外部接口"]
        direction LR
        X1["Open-Meteo<br/>天气 + 地理编码"]
        X2["汇率 三源降级<br/>exchangerate-api<br/>er-api / jsDelivr"]
        X3["ipwho.is<br/>IP 归属地"]
        X4["MyMemory<br/>翻译"]
        X5["抖音 / B站<br/>视频解析"]
    end

    BR --> NG
    APK --> NG
    BLOG --> NG
    NG --> TB
    NG --> AC
    NG --> BLOGST
    TB --> DB1
    AC --> DB2
    TB -- "/api/auth/* 代理转发" --> AC
    BR -. 浏览器直连 .-> X1
    BR -. 浏览器直连 .-> X2
    BR -. 浏览器直连 .-> X3
    BR -. 浏览器直连 .-> X4
    TB --> X5
```

**几个容易看漏的点：**

- 前端调第三方接口是**浏览器直连**，不经过服务器 → 所以 nginx 的 `connect-src` 一旦收窄，工具就整片失效（2026-10-02 那次事故就是这个）
- `toolbox.service` 一个进程干两件事：对外是 API，同时托管整个前端静态目录
- 博客和工具箱**共用同一个后端进程**（博客的 `/api/` 也反代到 8792）
- 登录走的是独立账号服务，工具箱只做代理转发

## 图 2 · 登录链路

```mermaid
sequenceDiagram
    participant U as 用户浏览器
    participant T as toolbox :8792
    participant A as liuli-account :8791
    participant D as accounts.db

    U->>T: POST /api/auth/email-codes
    T->>T: 限流 authproxy 40/分/IP
    T->>A: 转发 + X-Forwarded-For(真实IP)
    A->>A: 限流 email-codes 5/分/IP
    A->>D: 写验证码哈希(5 次尝试上限)
    A-->>U: 邮件发出

    U->>T: POST /api/auth/login
    T->>A: 转发
    A->>D: bcrypt 校验
    A-->>U: accessToken(HS256) + refreshToken
    Note over U,T: 之后带 Bearer 访问 /api/sync、/api/me
    T->>T: 本地验签(读账号服务 .env 的 JWT_SECRET，只读)
```

## 图 4 · 38 个工具的分类结构

```mermaid
flowchart LR
    T(("百宝箱<br/>38 个工具"))
    T --> IMG["🖼️ 图片 14 个"]
    T --> TXT["📝 文本 8 个"]
    T --> CAL["🧮 计算 10 个"]
    T --> NET["🌐 网络 6 个"]

    IMG --> I1["本地处理<br/>去水印 / 压缩 / 加水印 / PDF<br/>格式转换 / 拼接 / 取色 / Base64<br/>文字卡片 / 九宫格 / 屏幕检测"]
    IMG --> I2["需服务端<br/>OCR 识别 (tesseract)"]
    IMG --> I3["二维码生成 / 条形码 / 二维码识别"]

    TXT --> TX1["JSON 格式化 / JSON↔CSV<br/>Base64 / URL 编解码 / 文本转换<br/>Markdown 预览 / 摩斯电码 / 打包 ZIP"]

    CAL --> C1["随机密码 / 时间戳 / 单位换算<br/>颜色工具 / 进制转换 / UUID<br/>哈希 MD5-SHA / 随机决定 / 倒计时"]

    NET --> N1["浏览器直连第三方<br/>天气 / 汇率 / IP 查询 / 翻译"]
    NET --> N2["经自建服务器<br/>视频下载 / 视频转音频 (ffmpeg)"]
```

**规律**：能纯前端做的全部纯前端（工具本地运行、秒级响应、不上传）；需要算力或绕跨域的三类——OCR、视频解析、视频转音频——才走自建服务器。

## 图 5 · 一次工具访问的数据流（含埋点）

```mermaid
flowchart LR
    A["点击工具"] --> B["前端渲染，本地执行"]
    B --> C["POST /api/track<br/>action=open"]
    C --> D[("tool_usage 表<br/>IP / 账号 / 工具 / 停留时长")]
    B --> E["关闭工具"]
    E --> F["POST /api/track<br/>action=dwell + 停留毫秒"]
    F --> D
    D --> G["admin.html<br/>汇总 / 排行 / 明细"]
```

埋点是**匿名可用**的：未登录记 `anon`，登录记账号标识。后台按真实客户端 IP 限 30 次/分钟。
